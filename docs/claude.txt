## Cuánto le lleva a un junior

**Depende de qué versión.** El mínimo que aprueba la checklist —un script de ~100 líneas, argparse simple, 5 tests— son **4 a 6 horas**.

Esta versión, para un junior que ve generadores y pytest por primera vez: **20 a 35 horas ≈ 3 a 5 días** efectivos.

| | |
|---|---|
| Entorno (venv, ruff/black en VS Code, pyproject) | 2–4 h — casi todo peleando con el intérprete y formateadores duplicados |
| Git: .gitignore, ramas, Conventional Commits | 1–2 h |
| Datos de ejemplo | 1–2 h |
| Parseo CSV + modelos | 3–5 h — encoding, BOM y `newline=""` son 2 h de misterio la primera vez |
| Estadísticas | 1–2 h |
| Reporte (tabla alineada, json, csv) | 2–4 h — el `f"{v:>{ancho}{fmt}}"` cuesta |
| CLI con argparse | 2–4 h |
| 70 tests (fixtures, `tmp_path`, `capsys`, `parametrize`) | 4–8 h — lo más caro, todo concepto nuevo |
| README + documento | 2–4 h |
| Depuración y rehacer el historial | 2–4 h |

Si ya usó pytest y argparse antes, baja a **8–12 horas**. El multiplicador real no es escribir el código: es que la mitad de los temas de la semana (generadores, fixtures, conventional commits) se aprenden mientras se usan.
